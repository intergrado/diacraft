DiaCraft/Changelog

Changelog

DiaCraft 0.2.4 adds seven stencils of notation shapes, for UML class, use case and sequence diagrams, BPMN, the C4 model and crow’s foot and Chen database diagrams, each with a template; alt text for shapes, pages and masters, with an Accessibility pane that checks for what is missing; rows and sections in the ShapeSheet window; Join, Trim, Offset, Fit Curve and Reverse Ends; right-to-left editing; shell completions for the command line; and an .rpm package for Fedora. DiaCraft 0.2.0 was the first public release, and 0.2.4 keeps all of it: a free, open-source diagram editor for Linux, Windows, macOS and the browser. It opens, edits and saves VSDX and OpenDocument drawings, and keeps new drawings in its own .diacraft format.

New in 0.2.4

0.2.4 adds seven stencils of notation shapes drawn by the project, 88 shapes in all, with a template for each: UML class, use case and sequence diagrams, BPMN, the C4 model, and crow’s foot and Chen database diagrams. Shapes, pages and masters get alt text, typed in the Format Shape pane and checked in an Accessibility pane, and the ShapeSheet window adds and deletes rows and sections. Join, Trim, Offset and Fit Curve join the shape operations, Reverse Ends turns a connector round, and a key doubles or halves the connection points of a shape. A right-to-left paragraph is mirrored and edited right to left, and text is drawn in the language of its run. OpenDocument drawings carry DiaCraft’s dashes, glue and connection points to other programs. The command line gets shell completions and manual pages, an agent’s files can be kept to folders you choose, and the release has an .rpm for Fedora. Many fixes come with it, among them the two issues reported on GitHub: theme colours lost from some VSDX files, and a connector that could not be glued to a shape with no connection points.

  • UML class and use case diagrams. File → New has UML Class and UML Use Case, each opening its stencil beside the Basic Shapes. UML Class has Class, Interface, Enumeration, Package, Data Type, Object and Note, and eight lines: Association, Directed Association, Aggregation, Composition, Generalization, Realization and Dependency, routed at right angles, and a straight Note Link. A class is three compartments, its name, its attributes and its operations: type a line in one and the class grows by a line, in the same undo step, and a resize changes only its width. Typing on a selected class edits its name, a double-click on a compartment edits that compartment, and setting its Abstract field in the Shape Data window makes the name italic. An interface, an enumeration and a data type show their keyword above the name. UML Use Case has Actor, Use Case, Subject and Note, and Association, Include, Extend, Generalization and Note Link lines, drawn straight; Include and Extend carry their keyword as the line’s text. A package and a subject are containers: a shape dropped inside one joins it and moves with it.
  • UML sequence diagrams. The UML Sequence template opens a stencil of 14 shapes: Lifeline, Actor Lifeline, Activation, Combined Fragment, Destruction, Operand Separator, Interaction Use and Note, and the Message, Asynchronous Message, Reply Message, Create Message, Self Message and Note Link lines. A lifeline has twenty pairs of connection points down its stem, at the same heights on every lifeline, so a message glued between two lifelines at one step is level and stays level when they move, and the points follow a lifeline that is made taller. A Combined Fragment is a container whose tag shows its operator, a Shape Data field of twelve choices from alt, opt, loop and par to consider. A Self Message loops out from one lifeline and back, and stretches when the lifeline moves.
  • BPMN process diagrams. The BPMN Diagram template opens BPMN Shapes, 19 shapes after BPMN 2.0.2: Task, Gateway, Start Event, End Event, Intermediate Event, Sub-Process, Expanded Sub-Process, Call Activity, Data Object, Data Store, Message, Group, Text Annotation, Pool and Lane, and the Sequence Flow, Message Flow, Association and Data Association lines. A shape’s variant is a field in the Shape Data window, and the shape draws its marker: a task’s type, an event’s trigger and whether it interrupts, a gateway’s type, a loop, multi-instance, ad hoc or compensation marker, and the thick, dotted or double border of a call, an event sub-process or a transaction. A Pool dropped on the page makes a pool with one lane, and a Lane dropped on a pool adds a lane to it. A flow keeps the line pattern BPMN gives it: a format that would change it is refused in words.
  • C4 model diagrams. The C4 Model Diagram template opens a stencil of 12 shapes: Person, Software System, Container, Component, Database Container, Queue Container, Boundary, Deployment Node, Infrastructure Node, Diagram Title, Key and the Relationship line. An element shows its name, a type line such as [Container: Rust] and its description, from its Shape Data fields, and a relationship shows its description over its technology. The colours follow the page’s theme from the moment a shape is dropped, and an element marked External turns grey. A Boundary and a Deployment Node are containers, deployment nodes nest, and the Key shows a sample of each kind in the same colours.
  • Crow’s foot and Chen database diagrams. The Crow’s Foot Database Notation and Chen’s Database Notation templates open their stencils. Crow’s foot has Entity, Entity with Keys and Note, and the Relationship, One to One, One to Many, Many to Many and Note Link lines. Each end of a relationship is a Shape Data field of four choices, exactly one, zero or one, one or many and zero or many, and draws its mark; a relationship that is not identifying is dashed. An entity is a header over its attributes, and it grows as you type them. Chen has Entity, Weak Entity, Relationship, Identifying Relationship, Attribute, Key Attribute (underlined), Multivalued Attribute, Derived Attribute (dotted) and Associative Entity, and the Link and Total Participation lines, the second a double line.
  • Shapes made of parts. A class, an entity, a lifeline, a combined fragment, a BPMN event and the C4 key are each a group of parts that follow it. A click selects the whole shape, a drag moves it whole, typing goes to its name, and its tile in the Shapes window draws its parts. The new shapes save and reopen in .diacraft, VSDX and .odg files, and other programs that read the .odg draw their outlines, except BPMN’s Expanded Sub-Process, which they draw as a rectangle. Shapes, stencils and templates
  • Alt text, and an Accessibility pane. The Format Shape pane has an Alt Text tab, with a Title and a Description for the shapes selected and Clear Alt Text, and Edit Alt Text in a shape’s right-click menu opens it; the Page Setup dialog has an Alt Text tab for the page. A shape dropped from a master shows the master’s alt text in grey until it has its own, and Use master’s title and Use master’s description give it back. Review → Check Accessibility opens the Accessibility pane, which lists the shapes and pages with no alt text, alt text that holds a file name or a web address, pages that keep a default name such as Page-1 and hyperlinks with no description, checks again after each edit, and takes you to each one, with a button that puts it right. The same work is done by command: shape.alt_text, page.alt_text and master.alt_text read, set and clear the title and the description, and review.check_accessibility lists the findings, each with the command that puts it right. An SVG export gives each shape a title and a description from its alt text (its name, when it has none) and the page’s alt text to the file, and alt text is kept in VSDX and .diacraft files, and a shape’s in an .odg as its svg:title and svg:desc. Alt text and the accessibility check
  • Add and delete rows and sections in the ShapeSheet window. The Sections and Rows groups of the ShapeSheet Design tab insert and delete sections and rows: Insert in Sections opens a card of check boxes for the sections the sheet can take, and ticking several adds them as one step of Undo. The right-click menu of a cell, a row’s number or a section’s header has Insert Row (before the selected row), Insert Row After (in Geometry), Delete Row, Insert Section and Delete Section. A control the rules refuse is dimmed, and its tooltip says why: the rows of text, a section that cannot go, and a Geometry section that holds an Ellipse or an Infinite Line row alone. The foot of the sheet says what was done, and how many rows and formulas were numbered again. Shape Data, Link and Shape Action add a row to the sheet, and Edit Formula, or Ctrl+E, opens a larger editor of several lines for the formula of the cell selected.
  • Join and Trim. Join makes one shape of the shapes and lines selected, with each run of paths whose ends meet as one path, and Trim cuts the shapes selected wherever their paths cross, touch or meet themselves, into a shape for each piece. Both are in the Operations menu at the end of the Draw tab and on the Developer tab, and run as shape.join and shape.trim, each one step of Undo.
  • Offset and Fit Curve. Offset draws new shapes beside each shape selected, one on each side of its outline at the distance you give (outside and inside a closed one), with the line of the original and no fill, and keeps the original. Fit Curve remakes the paths of a shape from fewer segments within a tolerance, with circular arcs where a path is round. Offset in the Operations menu opens a dialog for the distance, 0.25 inch or 6 mm at first, and Fit Curve, a row of the Draw tab’s Operations menu, a dialog for the tolerance and three options; they run as shape.offset and shape.fit_curve.
  • Reverse Ends. Reverse Ends swaps the begin and the end of the connectors and lines selected, with their glue, so the arrowhead is at the other end, the route is the same line walked the other way and the label stays where it is. It is in a connector’s right-click menu, under Home → Arrange → Position → Rotate Shapes and in the menu of the Connector button on Home → Tools, and Ctrl+Alt+R (Command+Option+R on a Mac) does the same; connector.reverse_ends runs it by command.
  • Double and halve connection points. A DiaCraft extra: Ctrl+Alt+K (Command+Option+K on a Mac) doubles the connection points of the edge of a shape under the pointer, or of every edge of the shapes selected, by adding a point in the middle of each gap, and Ctrl+Alt+Shift+K halves them again, taking away only the points the last doubling added. A shape’s right-click menu has a Connection Points submenu, and Home → Tools → Connection Point has the same two rows. The points there stay where they are and every connector stays glued, an edge whose new points would be closer than the minimum distance (3 mm on paper at first, set in File → Options → Advanced) is left as it is, and shape.connection_points does the same by command. The points are saved and opened again in .diacraft, VSDX and .odg files.
  • Right-to-left text. A paragraph turned right to left (Home → Paragraph → Right-to-Left) mirrors its indents, its alignment, its bullet and its tab stops, and the text box edits it right to left, as it is drawn: the caret and the selection follow the screen, and Home and End go to the first and the last character of a row. The window’s fonts take a face for Arabic and one for Hebrew from the faces on your computer, so those letters show in its menus and boxes. Japanese and Korean vertical text is underlined on the right.
  • Text in the language of its run. Each run of text is drawn and measured in its language: the one its file gives it, or the drawing’s own. The text shaper and Change Case use it, and TEXTWIDTH and TEXTHEIGHT measure a text as it is drawn. An OpenDocument drawing’s runs keep their languages, and the drawing its own (dc:language), when it is opened and saved again.
  • Fix: copy and paste of text with other programs. Copy and paste of text now works between DiaCraft and other programs on Windows, macOS and Linux: text in shape labels and in every text field goes to the system clipboard and comes back from it.
  • Hollow line ends take the shape’s fill. The inside of a hollow line end, such as an open triangle, square or circle, is painted with the fill of the shape that holds the line, its colour, transparency, pattern or gradient, and its outline keeps the line’s colour, in the window and in PNG, SVG and PDF exports. A connector DiaCraft makes has no fill, so its hollow ends stay see-through until you give it one.
  • Shapes dropped on a page of another drawing scale. When a master drawn at one scale is dropped on a page drawn at another, the shape keeps its size in the drawing while the two scales are within a factor of eight of each other, and beyond that it keeps its size on paper, with its DropOnPageScale cell set to the ratio. Every way of dropping follows the rule: the Shapes window, AutoConnect, a template, a stencil file’s masters, BPMN’s Pool, the command line and MCP. A built-in shape is the same figure on paper as it is at 1:1: a class and an entity keep their height, a lifeline its head, a package its tab and a rounded box its corners, since the fixed lengths inside them follow the scale. BPMN’s Pool is dropped at every scale (a page drawn at 1:6 to 1:8 refused it). A drawing saved as OpenDocument Graphics and opened again keeps these figures: the lengths and markers of a group follow the page’s scale as they did before the save, and so does the text block of a line. Paste, Duplicate and Change Shape keep a shape’s size.
  • Compound lines drawn as their bands. A line with a compound type, such as a double line or a thick line beside a thin one, is drawn as two or three bands that share its weight, where it was drawn as one line.
  • Formulas across pages, and SETF. A formula that reads a cell of another page, through Pages[...], is worked out in the same edit as the cell it reads, and so are the formulas that read the document’s sheet, a style or a master, and those that name a page when a page is renamed, added, copied, deleted or moved; the connectors of the pages they reach are routed again. A cell that reads a connector’s route is worked out in the edit that changes the route. SETF writes its target when its own cell is worked out, and only when what it reads changes, and the writes an edit leaves out past its limits are named in the status bar. Change Shape carries over the cells the new master’s ReplaceCopyCells names, a shape whose LockVariation is set keeps its variant when a theme or a variant is applied, and a double-click on a shape that calls OPENGROUPWIN() opens no text box.
  • OpenDocument drawings reach other programs with more of the drawing. When a drawing is saved as .odg, each of the 22 dash patterns is written as a dash other programs draw, such as LibreOffice Draw; the glue of a connector you reconnect, reverse, glue or free is written into the file, so other programs keep its ends on their shapes; doubled and halved connection points are written as glue points; and the formulas of a shape, such as one typed in the ShapeSheet, a colour given as RGB() or a pin, come back when the file is opened again.
  • The Comm-link in other programs. A Comm-link or a Self Message saved in an .odg is written as the zigzag or the loop it draws, so other programs draw it as it is, where they drew a straight line. One glued to shapes is written as a connector glued to them, so another program keeps it glued when a shape moves: it draws that connector as a straight line between the shapes, and DiaCraft reads the zigzag back.
  • A settings file. DiaCraft has a settings file, config.toml, which the desktop app, diacraft-cli run and the MCP server share, in your system’s settings folder: ~/.config/diacraft on Linux, ~/Library/Application Support/diacraft on a Mac and %APPDATA%\diacraft on Windows. The app writes it once when it first starts, so that you can find it, with the language of your text taken from your system. DIACRAFT_CONFIG_DIR moves it, and with DIACRAFT_NO_PREFS set a run reads and writes none. The browser version stores nothing.
  • Keep an agent’s files to folders you choose. diacraft-cli mcp --headless and diacraft --control take --automation-read-root and --automation-write-root, each as many times as you need: the commands an agent runs open files only inside the first and save, export and print only inside the second, and a path outside is refused in words that do not name it. DIACRAFT_AUTOMATION_READ_ROOT and DIACRAFT_AUTOMATION_WRITE_ROOT do the same where a client can set the environment and not the arguments, as in an MCP bundle. The MCP server tells the client which folders it keeps to. With no folder given, nothing is limited, as before.
  • Shell completions and manual pages. diacraft-cli completions bash, and zsh, fish, powershell or elvish, writes a script that completes the commands, their options and values, the command ids of run --cmd and drawings by their type; --program diacraft writes the app’s. diacraft-cli man writes manual pages, one for each command. The .deb and the .rpm install both. At a terminal the help is in colour and wrapped to the terminal’s width, and in a pipe it is plain; --color and NO_COLOR decide. Command-line guide
  • An .rpm for Fedora. The release has diacraft-0.2.4-linux-x86_64.rpm and diacraft-0.2.4-linux-aarch64.rpm, each made and tried in a container of the latest Fedora on a machine of its processor. sudo dnf install ./diacraft-0.2.4-linux-x86_64.rpm installs both programs, the launcher entry and icon, the licences, the shell completions and the manual pages; dnf says the package is not signed. The release now has sixteen downloads. Go to the downloads
  • Fix: DiaCraft on Windows when it cannot open its window. On Windows, DiaCraft that could not open its window did nothing. It now tries DirectX 12, a software adapter and OpenGL, and if none works it shows a message box with the reason, the log’s place and what to try (Issue 17).
  • Fix: a Windows start stopped by a crashing graphics driver. On Windows, a graphics driver that crashed or hung while DiaCraft tested it could stop DiaCraft from opening, start after start (Issue 17). DirectX 12 is now tested before Vulkan, the test of each graphics adapter is logged first and given up on after 12 seconds, and an adapter that ended a start is left out of the next one; diacraft.exe --reset-graphics tests it again.
  • Fix: the macOS download’s README. The macOS download’s README now walks through the exact boxes macOS shows for an app that is not signed yet, and says how to uninstall DiaCraft.
  • Page names of up to 31 characters. A page tab and the Name box of Page Setup take at most 31 characters, and a command that gives a page a longer name is refused in words; a name a file holds is kept as it is. A VSDX file DiaCraft writes lists its background pages first, and a plain Save keeps a file’s own order.
  • On this website. The home page shows the seven-minute video tour, with the 55-second Short beside it, and the feature comparison with Visio, draw.io and LibreOffice Draw is brought up to date for 0.2.4.
  • Fix: theme colours lost from some VSDX files. A .vsdx whose theme part has no relationship to the document, or whose cells hold THEMEVAL() and no saved value, was drawn with black lines and white fills, as if it had no theme. Such a theme part is now read when the document has no theme relationship, and a save that gives the document another one gives the part one too. A cell that holds a formula and no saved value is worked out wherever it is read: in the picture and the exports, the formatting controls, the ShapeSheet window and the commands that move, size and snap, and nothing is written into the file for it. (Issue 14)
  • Fix: a connector glued to a shape with no connection points. connector.add and connector.reconnect refused a shape that has no connection points, and so did the Connector tool, an end dragged onto it and AutoConnect. Such a shape is now glued to as a whole, its end placed on the shape’s box and moved with it. A connector or a line is still refused as a target, in words. (Issue 16)
  • Fix: connectors glued to a whole shape. A connector glued to a shape with no connection points now stays glued when the file is opened in Visio: DiaCraft writes the glue formulas Visio keeps. (Issue 16)
  • Fix: resized shapes drawn right in other programs. A shape dropped from a stencil and then made taller or wider was saved without the type of the rows of its outline that follow the new size, so a program that reads each row on its own (draw.io and LibreOffice Draw were found to) drew one edge of a Process or a Decision, or nothing, or the size the stencil gave it. Each such row is now saved with its type and in order, as the rows of Visio’s own files are. A file saved by an earlier release keeps its rows until the shape’s size is changed again.
  • Fix: notation connectors in other programs. Connectors from the UML, BPMN, C4, crow’s foot, Gane-Sarson, network and Chen stencils keep their arrowheads, dashes and see-through line ends when the drawing is opened in other programs.
  • Fix: DiaCraft’s own data in a VSDX file. A file saved as a Visio drawing now keeps DiaCraft’s own data in the same form Visio’s own files use, so Visio no longer logs an error for it.
  • Fix: the right master when shapes are copied between DiaCraft drawings in Visio. Copying shapes between two DiaCraft drawings in Visio, and dropping shapes from a DiaCraft stencil file there, now keeps the right shape: every master DiaCraft saves has an ID of its own that Visio tells apart, where it took the masters of one stencil, or at one place in two drawings, for one master and gave the first. Drawings and stencils saved by 0.2.3 get the new IDs the next time they are saved as Visio files.
  • Fix: Visio warnings about text values in a VSDX file. Drawings and stencils made with earlier DiaCraft versions, saved again as Visio files, no longer make Visio log warnings about the text values of containers, swimlanes and fields.
  • Fix: labels kept in .vsdx files. Names, titles and other text in Shape Data, user-defined cells and fields are now saved as text, and text fields are saved with a picture, so org chart, network, C4 and UML labels keep showing in .vsdx files.
  • Fix: text no longer piled on itself in other programs. Saved as a Visio Drawing, the title line of an org chart position, text formatted in part and the text of a drawing opened from an .odg no longer show as letters piled on one another in other programs.
  • Fix: a VSDX file’s default text. A VSDX file DiaCraft saves now states its default text alignment, line spacing and tab stops in its root style, so text DiaCraft centres is no longer left-aligned in other programs.
  • Fix: a language typed into a language cell. A language typed into a language cell, such as fr-FR, is saved into a .vsdx file as the plain tag Visio itself writes, so the language of the text is kept.
  • Fix: connectors drawn in DiaCraft, after a shape moves. Connectors drawn in DiaCraft are now routed again by Visio when you move a shape they join, instead of keeping tilted legs that stop short of the shape.
  • Fix: themes reach shapes through their masters. Themes now reach dropped shapes through their masters, as Visio’s own files do, so UML, BPMN, C4, crow’s foot and Gane-Sarson connectors keep their arrowheads and dashes in Visio after a theme is applied; and taking a theme off no longer shrinks connector arrowheads.
  • Fix: page names. A page can no longer take another page’s name (in any case) or a name like page1, and a drawing saved as a VSDX file (an .odg’s page1 and page2, or a repeated name) is written with the names Page-1, Page-2 and so on, with a word about it in the save’s warnings.
  • Fix: hyperlinks after a page is renamed. When a save to a VSDX file gives a page a new name (page1 becomes Page-1), the hyperlinks that name it, including an .odg’s page links, are rewritten to the new name.
  • Fix: shortcuts and AltGr. A shortcut runs only for the keys that name it, so Ctrl+Alt+K is not Ctrl+K, and a key press that typed a character, as AltGr does, runs none: the characters AltGr types go into a shape’s text or a ShapeSheet cell, and start their editing. On Windows, Ctrl with the left Alt key types the AltGr character too, as Windows makes it (built from how Windows reports the keys, and not yet pressed on a Windows keyboard).
  • Fix: menus, lists and notices. A menu taller than the window scrolls inside it, and the arrow keys bring the row they reach into view. A list in a menu, such as the dashes of the Line menu, opens beside its row and never over the menu. A notice too long for the status bar ends in an ellipsis, with all of it in a tooltip, and only one file dialog opens at a time. A character that none of the window’s faces has is drawn as a box.
  • Fix: the Shapes window’s search box. The Shapes window’s search box no longer has its bottom edge painted over by tiles scrolled beneath it, and the words in it are now centred in the box.
  • Fix: BPMN, UML sequence and C4 shapes in the Shapes window. The Shapes window now shows each BPMN, UML sequence and C4 shape as its own figure: the gateway, events, task and data object no longer draw all their hidden markers at once, and circles close.
  • Fix: formatting a BPMN event, gateway or task. Formatting a BPMN event, gateway or task no longer draws extra boxes: a line colour now changes only the outlines and markers, a fill colour fills the figure and no box round it, and a send task’s envelope follows the line colour.
  • Fix: square boxes under rounded themes. A UML class, interface, enumeration, data type or object, a Crow’s Foot entity, a UML package and the lanes of a BPMN pool or a cross-functional flowchart are no longer rounded piece by piece under the Tidepool and Plumline themes: each reads as one square-cornered box, with no notches where the pieces meet.
  • Fix: text taken out of a shape that shows its master’s. Taking the text out of a shape that shows its master’s text (for example a UML class compartment) now leaves it empty. The placeholder text no longer comes back, in the window, in exports, or after saving and reopening.
  • Fix: editing a shape that shows its master’s text. Editing a shape that shows its master’s text (a UML class’s + attribute : Type) now opens the box on that text, so you can select it, delete it or type over it.
  • Fix: connectors after a recalculation resizes a shape. A theme, a font size, a typed line, a formula or a master edit that resizes a shape now reroutes the connectors glued to it, as moving the shape does, so they no longer end up slanted.
  • Fix: the shape you drag from the Shapes window. The shape you drag is drawn at the size its drop will make, and snaps where the drop will put it, at any drawing scale.
  • Fix: clicking a shape’s name. Clicking the name of a shape selects the shape, even when the name sits outside it: under a BPMN event, gateway or data object, under a network device or a computer, or on a connector label moved off its line. A shape whose outline is under the click still takes it first.
  • Fix: drawings keep their stencils. A drawing saved as .diacraft or a VSDX type keeps the list of the built-in stencils that were open, and opens them again: a drawing from the Basic Network Diagram template reopened with the default stencils. A lane added to a cross-functional flowchart stays on its page.
  • Fix: what other programs put in a VSDX file stays in place. A comment or another program’s element inside a shape of a .vsdx stays after the row, cell or section it followed when rows and sections are inserted, deleted or written again, by the ShapeSheet, a connector’s route, a path you continue, Change Shape or Save As. A row or a Geometry section numbered again keeps its own element, so a second save in a session is no longer refused.
  • Fix: connectors written again for nothing. A connector that needs no line jump keeps the route the router made, so a page of right-angle connectors that cross nothing is no longer written again at every rebuild, and a route that differs only by the sign of a zero is not written again.
  • Fix: SETF over a value you typed. A SETF no longer writes over a value you typed into its target when another cell reads the SETF’s cell, or when you edit the cell it names.
  • Fix: a formula that names a cell in another letter case. A formula that names a cell in capitals or any other letter case, such as WIDTH/1 in*12, reads that cell and is worked out again when it changes; it read 0.
  • Fix: OpenDocument saves. A group of an .odg with a glue point of its own is saved after it is moved or resized, where the save was refused. Data given to a group of a flat .fodg is refused in words that name the group, where the save dropped it and said nothing. The check after a save no longer reports the font that every new drawing’s font table holds as missing, and a change of a shape’s data beside its alt text is saved.
  • Fix: flips and turned text in OpenDocument saves. A flip made in DiaCraft on a shape that came from an .odg file, and a turn of its text, are now kept when the drawing is saved as an .odg from a .diacraft file or a flat .fodg, and the glue points of a turned or flipped shape follow it. What a save cannot keep it says in words: a flip in a drawing that is saved from the .odg it was opened from, and a flip or a text of a 3-D shape or a fontwork.
  • Fix: a shape moved in front of or behind a group with no name. Saving a drawing again after a shape was moved in front of or behind a group with no name is no longer refused, in a flat .fodg and in an .odg.
  • Fix: dash patterns in an .odg. An .odg saved through DiaCraft keeps the dash pattern of every line, including a dash a style takes from its parent, and writes no dash name where the file named none.
  • Fix: a connector in a group, glued to a shape. A connector inside a group that is glued to a shape no longer stops a drawing from being saved as an .odg after a trip through DiaCraft’s own format and VSDX, and a file’s own connector ends are left as the other program wrote them.
  • Fix: fields and old org chart names in a .vsdx file. Page numbers, file names, dates and times in .odg drawings, and the names and titles of older org charts, keep showing when the drawing is saved as a Visio Drawing (.vsdx).
  • Fix: fields that stay fields across formats. Page numbers, page counts, dates, times and file names stay fields when a drawing goes from .odg to .vsdx and back, and fields made in DiaCraft are saved to .odg as fields.
  • Fix: spans of one text style in several shapes. An .odg that goes through .diacraft keeps every property of a text style shared by spans in two shapes, such as the sizes and weights of the Asian and complex scripts, where the second shape’s span was written with a new style that lost them.
  • Fix: OpenDocument drawings that would not open again. An .odg or .fodg that binds the svg prefix to another namespace, with a connector glued to a shape, was saved after the shape moved with a namespace declared twice on the connector: DiaCraft said it had saved, then could not open the file. Each prefix is now declared once on a tag, and a save that would write an attribute twice is refused in words.
  • Fix: VSDX files with a part of one repeated pattern. A .vsdx with a part that compresses more than a thousand times opened but could not be saved, as VSDX or as .diacraft. Such a part is now stored as it is, and the file saves.
  • Fix: lines whose ends are not numbers. An .odg line whose coordinate is no number, such as infcm or NaNcm, opened but could not be saved as .odg. The coordinate is now read as absent, the open says so, and the save writes what the shape’s cells say.
  • Fix: the page that is drawn by default. diacraft-cli export and convert to a picture with no --page, and the commands that take a page and are not given one, used the first page of the drawing, a background page in a file that lists them first. They now use the first page that is not a background.
  • Fix: the shape.delete command and glued connectors. The shape.delete command, and so the command line, the control channel and MCP, takes the connectors glued to the shapes it deletes, as the Delete key does; connectors: false leaves them with a free end.
  • Fix: a file named after an option. diacraft and diacraft-cli look for --help and --version only before a --, so a drawing named --help opens after it.

New in 0.2.3

0.2.3 adds the ShapeSheet window, which shows and edits the cells of a sheet, commands that read and set any cell of a drawing and add and delete its rows and sections, two network stencils, two new templates, the Layout and Routing tab of Page Setup and the Operations menu on the Draw tab. A connector with a fixed route keeps its corners when its shapes move, and OpenDocument drawings come back closer to the file they came from and give other programs more of their shapes’ outlines.

  • The ShapeSheet window. Turn on the Developer tab under File → Options → Customize Ribbon, then choose Developer → Shape Design → Show ShapeSheet, or Show ShapeSheet at the top of the right-click menu of a shape or the page. The sheet of a shape, the page or the document opens in a tab of an area below the drawing, beside it or in its place, and Drawing Explorer opens the sheets of styles and masters. Each cell shows its formula and its value. A cell the sheet holds is blue with a dot, an inherited one plain and an error in its own colour, and its tooltip says where it comes from. A group of cells is laid out as names and values in columns, and the name of a row whose formula has an error is red. The formula bar under the ribbon shows the whole formula of the cell selected, and the ShapeSheet Design tab shows formulas, values or both, and hides sections. A sheet of more than 30,000 rows opens and scrolls to its last row. Formulas and the ShapeSheet window
  • Edit cells in the ShapeSheet window. Double-click a cell or press F2 to edit its formula, start typing to replace it, or click in the formula bar, which edits the same text. Enter commits and goes down, Tab goes right, Shift+Enter and Shift+Tab go up and left, and Escape or the bar’s cancel button leaves the cell as it was. As you type, the bar shows what the formula works out to. A formula DiaCraft refuses stays open with the reason in words, and a fault in it is underlined. An empty formula clears the cell, which then inherits again from its master or style. Each change is one step of Undo, and the cells it worked out again are marked until your next change, with a count at the foot of the sheet. Ctrl+C and Ctrl+V copy a formula from one cell to another, and the arrow keys, Home, End, Page Up and Page Down move around the sheet. Drag a column’s edge to widen it, or double-click the edge to fit the column.
  • Read and set any cell from a program. sheet.set_cell and sheet.set_cells write a formula or a value into any cell of any sheet: a shape, a member of a group, a master, a page, a style or the document. Each call is one undo step and is applied whole or not at all, with up to 4,096 writes. The cells that read the cells written are worked out again, and an empty formula makes a cell inherit again. A cell protected by GUARD is replaced only when the call says force. sheet.read, sheet.cell and sheet.sections read a sheet as the window shows it, and sheet.evaluate works a formula out on a sheet without writing it. They run from diacraft-cli run, the MCP server’s command_run and the control channel.
  • Add and delete rows and sections from a program. sheet.add_row, sheet.delete_row, sheet.add_section and sheet.delete_section add and delete rows of Geometry, Connection Points, Controls, Scratch, Shape Data, User-defined Cells, Hyperlinks, Actions and the gradient stops, and add and delete sections, each as one undo step. A row inserted in the middle of a shape’s or a page’s section moves the rows after it up one number, every formula that named a moved row still names it, and so does a connector glued to a connection point that moved; a formula that named a deleted row reads #REF!. A row that a shape takes from its master is deleted for that shape alone, and an insert in the middle of rows a shape takes from its master first gives the shape its own copy of them, in the same step. A Geometry section that holds an Ellipse or an Infinite Line row holds that row alone. They run from diacraft-cli run, the MCP server’s command_run and the control channel.
  • The Operations menu on the Draw tab. The Draw tab ends with a Shape Operations group, whose Operations menu is the Developer tab’s: Union, Combine, Fragment, Intersect and Subtract. The shape operations no longer need the Developer tab turned on.
  • Two new templates. File → New has Data Flow Model (Gane-Sarson), which opens the Gane-Sarson shapes and the Basic Shapes, and Basic Network Diagram, which opens the two network stencils below and the Basic Shapes. The shapes of Basic Shapes, the Basic Flowchart, Gane-Sarson and the organization chart are now marked, in their masters, as shapes that connectors join.
  • Network Devices and Computers and Devices. Two stencils of 28 network shapes drawn by the project: a router, a switch, a firewall, a cloud, a wireless access point, a load balancer, a modem, the internet, an Ethernet bar and a ring network; seven servers, a desktop, a laptop, a rack server, a tablet, a mobile phone, a telephone, a printer, storage and a user; and two lines, the zigzag Comm-link and the Network Link connector. Each device has Shape Data in up to three groups, for its equipment, its network and, on a computer, its processor, memory, operating system and hard drive, and the label under a networked device shows its network name over its IP address as you fill them in. The devices follow the theme like any shape, and More Shapes lists both stencils under Network.
  • Tiles that show the shape. In the Shapes window, the tile of a built-in connector or line, such as the Data Flow connector or the Comm-link, shows its line ends and its pattern, and the tile of a group master, such as one of a stencil file you open, draws the group’s members instead of an empty box.
  • Line ends drawn from their masters. A custom line end, one that names a line-end master of the drawing, is drawn from that master, placed by its pin on the end of the line and in the line’s colour. Such an end used to be drawn as a standard arrowhead.
  • Typing on a group. Typing, F2, the Text tool and a double-click on a group send the text where the group’s IsTextEditTarget cell says. When it is FALSE, the text goes to the member on top of the group, so typing on a selected group edits that member’s text while the group stays selected. A double-click on a member you selected on its own edits that member.
  • Connectors with a fixed route keep their corners. When a shape moves, a connector glued to it that is set to Reroute As Needed, Never Reroute or Reroute on Crossover, or whose route you edited by hand, keeps the corners in the middle of its route where they are on the page, and its end legs stretch to follow the shapes, staying level or upright. The whole route used to stretch and turn with the line between the connector’s ends.
  • The Layout and Routing tab. The Page Setup dialog has a Layout and Routing tab, which the Design tab’s Layout launcher also opens: the page’s routing style and direction, Separate, Overlap and Appearance, which lines get line jumps, the jump style and its vertical and horizontal size. Spacing... opens a dialog of the gaps between shapes and connectors, with Defaults. A preview shows two boxes joined in the style chosen, crossed by a line with the jump the page would make. OK applies what you changed as one undo step, and a new style routes again the connectors that follow the page and reroute freely. A connector’s right-click menu has Right-Angle Connector, Straight Connector and Curved Connector, which change the connectors selected and route them again.
  • Routing settings by command. page.routing and page.set_routing read and set the page’s routing style, its spacing between connectors and shapes, and how its connectors are drawn, and a new routing style for the page routes again the connectors that follow it. connector.style takes routing styles with a direction (organization chart, flowchart, tree and simple, from top to bottom, left to right, bottom to top or right to left), which are saved with the drawing and drawn as right-angle routes. connector.path gives the corners of a connector’s route. shape.behavior and shape.set_behavior read and set how a shape takes part in routing, and gluing a connector to a shape marks the shape as one that routes go round, in the same undo step. These are settings: in 0.2.3 no connector is routed round other shapes.
  • Stretching shapes with a size lock. When several shapes are stretched together, a shape locked against a change of height keeps its height and is stretched in width, and one locked in width keeps its width and is stretched in height. A shape locked both ways, or locked one way and to its proportions, is left as it was, and the command lists it. When one shape is resized, a size that is locked and given by a formula is kept, and the shape is sized along its other axis.
  • New shapes reach other programs as they are drawn. When a drawing is saved as .odg, a new shape’s outline is written as the path it draws, with its arcs, its lines that are not filled and its hidden parts, where some of these used to make it a rectangle for other programs. Thirteen Basic Flowchart shapes, the Process and Data Store of Gane-Sarson and the 26 network devices are drawn by other programs as their own outlines. They draw a network device’s label inside its box, and the Comm-link as a straight line.
  • OpenDocument drawings come back closer to the file. When an .odg is saved as .diacraft and then as .odg again, more of it comes back as it was: styles that no shape uses, a master page or a style with no name, two styles of one name, the ids of shapes and of the shapes connectors are glued to, groups with no name, groups with a style or connection points of their own, a polygon whose outline DiaCraft could not read, and the text styles of runs and paragraphs as the file stated them. Where the file was written for an earlier version of ODF, the styles written are valid ODF 1.4: a font weight, slant or variant that ODF 1.4 has no value for is written as the nearest value it lists, and the exact value is kept in DiaCraft’s own attribute. A drawing of ODF 1.0 or 1.1 is written with each shape’s id in the form ODF 1.4 asks for as well, and its connectors stay glued to the same shapes. A new connector with a routing style that the format cannot say, which a save used to refuse, is written as a standard connector, and its style is kept in DiaCraft’s data.
  • Fonts kept through a VSDX file. When an OpenDocument drawing that declares several faces of one font family is saved as a VSDX type and then as .odg again, each face comes back declared, so the text keeps its font in other programs, where it used to fall back to another one.
  • Check a save before you make it. file.check_compatibility says what saving the drawing as a given type would carry in DiaCraft’s data and what it would lose, fails in the words the save would, and writes nothing.
  • The command line compares more closely. diacraft-cli compare --content matches the children of an element by what they are, so an element put in or taken out is one difference, and the elements after it are still compared with their own. roundtrip --via diacraft of an .otg writes an .otg.
  • Code scanning. GitHub’s CodeQL scans the shipped code, the workflows and the scripts of the website and the web app on every push to the main branch, on every pull request and once a week. Test and fuzz code is left out.
  • A Features page on this website. It describes everything that works in DiaCraft, area by area, and the menu’s Features goes to it. Read the features

New in 0.2.2

The editor, the command line and the drawing files are as they were in 0.2.1. What changed is how the MCP server is installed, one fix in the browser version, and some text on this website and in the documentation.

  • MCP bundles. A release now holds six MCP bundles, diacraft-mcp-<version>-<system>-<processor>.mcpb, one for each system and processor the downloads are built for, for example diacraft-mcp-0.2.2-linux-x86_64.mcpb. An app that installs MCP servers can open the file, and a directory of MCP servers can list it, so there is no configuration to write. A bundle holds the command line program, whose server is diacraft-cli mcp, and not the window: install the app to see a drawing. The server’s name in the official MCP Registry is app.diacraft/diacraft, and the registry’s entry names the six files by address and checksum. SHA256SUMS.txt now lists twenty files, the fourteen downloads and the six bundles. The bundles are not signed. The project ran the program in each one as its manifest says, but has not installed a bundle in an app that installs them.
  • The browser version keeps its canvas the size of its page. In a browser that reports the canvas’s size in CSS pixels instead of device pixels, such as the device emulation of a browser’s developer tools at a scale above 1, the window was laid out for a part of the page: half of it at a scale of 2. The app now holds the canvas to the page’s size times the device pixel ratio. Real high-density screens were not affected. Chrome 158 and Firefox 160 on Linux, set to scales of 1.5, 2 and 3, report the size correctly. A Mac’s screen, a phone and Safari were not tried.
  • The home page answers “How is DiaCraft made?” AI coding agents write most of the code and documentation, and a human maintainer decides what is built, in what order, and what ships. Read the answer
  • The roadmap names what comes next. After the 0.3 items, four features are scheduled, in this order: connectors that route around shapes and are routed again when a shape moves; a window that shows and edits a shape’s formulas, with a command that sets any cell; opening .drawio files; and more stencils of DiaCraft’s own. None of them is started. Read the roadmap

v0.2.0

The first public release, on 25 November 2026.

New drawings start in .diacraft

The first time you save a new drawing, the Save dialog offers DiaCraft’s own format, .diacraft, first. The file holds the drawing’s pages, shapes, styles and pictures, and keeps details that came from a VSDX or OpenDocument drawing without storing the original file. Opening an existing .vsdx or .odg and choosing Save keeps its file type.

Grid, ruler, guide and connection-point visibility travel with the drawing. Save after changing one of these settings to see it again when you reopen the file. Work with .diacraft files

Save across VSDX and OpenDocument

Choose File → Save As and pick a type. A drawing can be saved from one family into the other.

  • Save a VSDX drawing as an OpenDocument drawing (.odg) or template (.otg), and an OpenDocument drawing as any of the six VSDX types. Either can be saved as .diacraft, and a .diacraft drawing as any of them.
  • Where the new type cannot hold part of a drawing, a card over the drawing tells you what, in words. After the save, DiaCraft reads the new file back, compares it with the drawing and names what differs.
  • If you save a drawing that has a macro project as a VSDX type that cannot carry macros, DiaCraft asks whether to leave them out or to save as the macro-enabled type instead. It keeps the project as file data and never runs it.
  • Start an untitled drawing from an .otg template. Your first save gives the drawing its own filename.
  • A flat OpenDocument drawing (.fodg) is written back to its own file by Save, and Save As writes it as another type.

Inside the editor

The window has a ribbon, a Shapes window, rulers and a grid, page tabs and a File view. In this release you can:

  • Start from a blank drawing or one of four templates: Basic Diagram, Basic Flowchart, Cross-Functional Flowchart and Organization Chart.
  • Drag shapes from seven built-in stencils, including Basic Flowchart and Gane-Sarson, or from a stencil file you open.
  • Join shapes with connectors that stay glued as you move them. Use AutoConnect, choose right-angle, straight or curved lines, and drag a handle to move a leg.
  • Format text, fills and lines, with gradients, patterns, transparency, shadows and Quick Styles, and change the colours of a page with a theme and its variants.
  • Draw rectangles, ellipses, lines, arcs and freeform shapes, and combine shapes with Union, Combine, Fragment, Intersect and Subtract.
  • Use pages and background pages, layers, containers, swimlanes, callouts, comments and Shape Data, lay a page out again with Re-Layout Page, and find and replace text.
  • Export a page as PNG, SVG or PDF, or print with a preview of the sheets.

DiaCraft in your browser

The same editor runs in a browser tab at diacraft.app, with nothing to install. It opens and saves .diacraft, VSDX and OpenDocument files on your computer and exports PNG, SVG and PDF. It sends no drawing anywhere and stores nothing in your browser. It can open in a window of its own, and it asks before a tab with unsaved changes is closed or reloaded.

Very large drawings, your own fonts, printing to a printer, the command line and the MCP server are for the desktop app: in the browser, Print saves the PDF that a printer would be given. The browser version has been run in current releases of Chrome and Firefox on Linux. What the browser version needs and what it keeps

From the command line and AI agents

diacraft-cli convert saves a drawing as another type and diacraft-cli export makes a picture of a page, without opening a window. Each prints a line of JSON that says what it wrote. To check a conversion, use diacraft-cli roundtrip with --via diacraft: for a VSDX or ODG package, the report compares the original content with the copy written back to the source format.

Through the MCP server, diacraft-cli mcp, an AI agent can create a diagram in a session of its own or edit the drawing you see on screen, with the same commands the window uses. Command-line guide · Agent guide

Also in this release

  • The Save dialog sets the extension. Choosing a file type in the Save dialog changes the extension of the name to that type’s, on Windows, macOS and Linux. An extension you type yourself is kept. Export and Save as PDF use the same dialog.
  • The splash at full size on dense screens. The splash and About DiaCraft are the same size on every screen, and on a high-density screen they are drawn from the full-resolution artwork, so they stay sharp.
